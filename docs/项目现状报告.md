## 二、核心功能（从代码推断）

1. **打字测速**：从词库随机取 180 词，contenteditable 输入区逐词输入，
   空格/回车换词，60 秒倒计时结束后弹出成绩 Modal（词/分、字/分、准确率）。
2. **逐词实时校验**：`matchSourceAndTarget` 拟合匹配，前缀正确时把"当前词"裁剪成
   剩余后缀（渐进式高亮效果），出错词在已完成区以删除线标红。
3. **词库选择**：7 个分类，`import.meta.glob` 动态加载 JSON，localStorage 缓存。
4. **明暗主题**：跟随系统偏好 + 手动切换，持久化到 localStorage，同步 antd 主题算法
   与 Chart.js 配色（MutationObserver 监听 `data-theme`）。
5. **中英切换**：切换开关同时切换 i18n locale 与"是否显示中文释义"。

## 四、代码质量粗评（最大的问题）

1. **零测试覆盖**：核心打字匹配逻辑（`utils.ts`、`TypingArea.vue` 的
   `updateContent/changeCurrentWord`）完全无验证，这类逐字符状态机最需要回归保护。
2. **组件直接变异 props 引用的数据（确认的数据污染 bug，详见 BUGFIXES.md）**：
   `TypingArea` 把 `props.data` 的内部数组按引用 push 进 `onComing`，打字过程中
   `onComing[0][0] = ...slice(pos)` 会把前缀从源数据里"剪掉"，同一词库多轮练习后
   词条被截断。源码注释里作者自己也标注了 `NOTE: 数据引用bug`。
3. **巨型单文件组件**：`TypingArea.vue` 498 行（逻辑+模板+样式），计时器、匹配、
   DOM 操作（`input.value.contentEditable = false`）混在一起，逻辑无法单独测试。
4. **隐式 DOM 依赖**：`startingIndicator.value.style` 直接操作内联样式、
   `event.target.textContent` 直接读写 contenteditable，组件测试必须跑在真实 DOM
   环境（jsdom）并 mock 少量 API（matchMedia、canvas 2d、Modal）。
5. **工程细节**：pre-commit 钩子只做 `build + 提交 dist`，不跑 lint/test；`dist` 入库
   导致每次提交携带构建噪声；`loading` 状态缺失时 `loadWordsData` 对未知分类返回
   `undefined` 而调用方未判空。

## 六、已发现、待测试确认的问题清单（预判）

1. `TypingArea` 变异 props 数据（见上文 2）→ 计划最小修复：push 时拷贝元组。
2. `App.vue` 下拉选项用插值渲染 `&nbsp;` 字面量 → 选项文本会显示 `xxx&nbsp;(3224)`
   字符串而非空格（待组件测试确认后修复）。
3. `replaceBlankWord` 只替换第一个空格（SAT 词库有 26 个含空格词条，若一词含两个
   空格则第二个空格不会被替换）→ 记录为遗留问题，不改变行为。
4. `loadWordsData` 未匹配到分类时返回 `undefined` → 调用方 `words.default` 会抛
   TypeError，属防御性缺失，记录不修（无调用路径会触发）。
