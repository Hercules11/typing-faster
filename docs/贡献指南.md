# 贡献指南

> 规则背后的原因在"为什么"里；改规则前先确认存量代码能过，或以独立提交批量修复。

## 命令

```sh
pnpm check:all        # 提交前完整门禁：lint:check + typecheck + test + build + e2e
pnpm lint:fix         # ESLint 自动修复（空行/花括号等规则均可 --fix）
pnpm lint:check       # 只读校验，--max-warnings 0（warning 也算失败）
pnpm typecheck        # vue-tsc
pnpm test / test:e2e  # 57 个单测 / 6 条 Playwright 冒烟
```

## TypeScript 严格选项（tsconfig.app.json）

在 `@vue/tsconfig`（含 `strict`）之上启用：`noUncheckedIndexedAccess`（索引访问
视为可能 undefined，必须判空）、`exactOptionalPropertyTypes`（可选属性禁止显式
赋 undefined）、`noImplicitReturns`、`noImplicitOverride`、`noFallthroughCasesInSwitch`、
`noUnusedLocals/Parameters`、`useUnknownInCatchVariables`。

新增代码的常见落点：数组/字典取值后先判空（`const first = arr[0]; if (!first) ...`），
`withDefaults` 里不要写 `prop: undefined`。

## Lint 要点（.eslintrc.cjs）

- 在 vue3-essential + eslint:recommended + TS 推荐之上叠加：
  `no-explicit-any`（mock 场景定义接口，参考测试里的 `FakeChartInstance`）、
  `consistent-type-imports`、`no-duplicate-imports`、`eqeqeq`、`curly`、
  空行规则（语句/代码块之间空行、连续空行 ≤1、SFC 块之间空行）、
  `vue/require-prop-types`（props 必须类型化声明）。
- 类型导入与 `no-duplicate-imports` 共存：用内联写法 `import { x, type Foo }`。
- 例外：`consistent-type-imports` 对 `**/*.{js,cjs}` 关闭（无 TS parser services
  会直接崩溃，见 overrides 注释）。
- 格式问题交给 Prettier；`dist/` 不参与 lint（有意入库的部署产物）。

## 测试规范

| 层     | 对象           | 环境          | mock 原则                                                |
| ------ | -------------- | ------------- | -------------------------------------------------------- |
| 纯逻辑 | `src/utils.ts` | jsdom         | 不 mock，词库加载走真实 `import.meta.glob`               |
| 组件   | `.vue`         | jsdom         | 只 mock 外部依赖：ant Modal、chart.js（jsdom 无 canvas） |
| E2E    | 完整应用       | 真实 Chromium | 什么都不 mock                                            |

- 组件测试用 `renderWithI18n` 挂载（与 `main.ts` 同一套 i18n/antd 组件注册；
  新增 antd 组件时同步更新 `main.ts` 与 `test-utils.ts` 两处）。
- 总原则：**测行为不测实现**——用例命名描述行为，断言用户可见的东西
  （文本、class、localStorage、emit），禁止空壳用例和凑覆盖率的机械用例。
- 全项目只有两处 mock：ant Modal（命令式弹层，mock 捕获 `onOk/onCancel` 驱动
  重置流程）和 chart.js（jsdom 无 canvas，mock 捕获构造参数断言数据来源）。
  除此之外禁止 mock：被测组件内部逻辑、被测工具函数、词库 JSON。
- jsdom 注意：`contentEditable` 赋值不反射到 attribute，断言用属性值；事件后
  `await nextTick()`；`matchMedia` 已在 `setup.ts` stub。
- 已知噪音：`HTMLCanvasElement.prototype.getContext Not implemented` 是 jsdom
  未实现 canvas 的无害 stderr（图表在单测中已 mock）；要消音可在 setup.ts stub，
  不必安装 `canvas` 原生包。
- 覆盖率：全局语句/行 ≥ 60%，硬阈值只用来**防止劣化**，不追求指标
  （vitest 2 不支持 per-glob 阈值，不做人工核对；当前全局 91%、`utils.ts` 98%，
  数字以 `pnpm test:coverage` 报告为准）。入口/纯类型/纯图标组件已排除。
- 组件会改写 props 数组元素时，测试传副本避免用例间串扰。

## 提交规范（Conventional Commits）

格式 `type(scope): 中文简述`。常用 type：

| type                     | 用途                                                         |
| ------------------------ | ------------------------------------------------------------ |
| `feat`                   | 新功能                                                       |
| `fix`                    | bug 修复（用户可见行为变化同步记录到 `docs/现状.md` 第五节） |
| `test` / `docs`          | 测试 / 文档                                                  |
| `chore` / `build` / `ci` | 构建、依赖、工程配置                                         |

依赖变更必须在提交信息里写明原因。

## Pre-commit 与 CI

```
git commit
  -> lint-staged（暂存文件 eslint --fix + prettier --write）
  -> pnpm test
  -> pnpm build（vue-tsc + vite）
  -> git add dist/（Pages 部署产物入库）
```

不要用 `--no-verify` 绕过。CI：`docs/ci/test.yml` 模板（lint + typecheck + 单测 +
e2e），复制到 `.github/workflows/` 即启用。
