# 开发指南

> 只写"为什么"和"怎么流转"，不重复代码能自答的"是什么"。函数签名看源码，类型看 `src/types.ts`，命令看 README。

## 1. 架构总览

Vue 3 + Vite 单包应用。组件只做 UI 编排与 DOM 副作用，领域逻辑收在 composables，
纯函数在 utils，localStorage 读写统一走存储层：

```
index.html -> main.ts（i18n + antd 按需注册）
    -> App.vue（纯 UI 编排：组装 composables + 两个确认弹窗）
         |-- useTheme     主题：localStorage + <html data-theme> + antd 算法
         |-- useLocale    中英开关 -> i18n locale
         |-- useWordBank  词库加载 / 随机 180 词 / 自定义词库 CRUD
         |-- CustomWordModal  自定义词库录入（三态图标确认按钮）
         |-- TypingArea   打字区 UI：contenteditable + DOM 副作用 + 结算弹窗
         |     |-- useCountdown     60s 倒计时（结束同 tick 触发 onFinish）
         |     `-- useTypingInput   输入状态机（纯逻辑，不碰 DOM）
         `-- GraphicsArea Chart.js 分布直方图（MutationObserver 随主题变色）
```

分层规则：**组件 -> composables -> utils -> utils/storage -> localStorage**。
谁持有状态、谁做 DOM，见各 composable 顶部注释。

## 2. 核心数据流

### 2.1 词库加载与随机取词

```
currentSelect 变化 / 挂载
  -> loadWordsData(cate)         先查 localStorage 缓存，未命中动态 import JSON 并写缓存
  -> 归一化为 { default: [[word, trans], ...] }
  -> 词库 > 180 条：随机偏移取连续 180 条；<= 180 条（自定义词库常见）：全量
  -> replaceBlankWord 把词内空格转 "_"（空格被"换词"交互占用）
  -> wordsData 传给 TypingArea
```

### 2.2 打字主循环

```
contenteditable 输入（updateContent，在 useTypingInput）
  -> 首次输入启动倒计时（宿主回调隐藏"开始输入"提示）
  -> Enter / 空格：提交当前词入 hasFinished，队列前移，清空输入框
  -> 普通字符：前缀拟合匹配（matchSourceAndTarget），
     正确则把当前词裁剪成剩余后缀（待打区"吃掉"前缀的推进效果），错误标红
  -> 60s 到点：同 tick 内 time 归 0 + 禁输入 + 结算 Modal
  -> 结算确认/取消：resetAllData（重置状态 + DOM + 通知父组件换词重开）
```

### 2.3 自定义词库

```
弹窗输入标题 + 纯英文文本
  -> 实时提取（小写/去重/保留连字符撇号），按钮 加号/红叉/绿勾 三态反馈
  -> 确认：不足 180 词复制整份扩充到超过 180
  -> 写入 localStorage（纯数组）+ 索引，自动选中开始
删除：下拉项行内图标 -> 确认 -> 移除数据与索引，删的是当前项则回退默认词库
```

## 3. 关键决策记录

改代码前先看这里，避免推翻已权衡过的决定；要推翻请在此处补一条理由。

1. **词库缓存的两种形状**：内置词库缓存保留了 ES 模块的 `{default: [...]}` 包装
   （历史产物），自定义词库是纯数组。选择在 `loadWordsData` 读取处**归一化**而不是
   迁移旧缓存——零迁移成本，调用方无感。
2. **自定义词库不足 180 词时复制整份扩充**：单次测试随机取 180 词，短文本撑不满
   一分钟；复制比"按需循环取词"简单且对统计无影响。
3. **localStorage 封装放 `utils/storage.ts` 而不是 composable**：存储不是响应式
   状态，且被 utils 层使用；composable 会被 utils 反向引用，是分层倒置。
   键名收口在 `STORAGE_KEYS`，禁止在组件里硬编码。
4. **useTypingInput 纯逻辑不碰 DOM**：contenteditable 的 DOM 副作用（禁输入、
   清空、提示动画）留在 TypingArea，通过 `onFirstInput`/`onFinish` 回调接线。
   这是组件与状态机的分界线，新功能请沿用。
5. **不引入 Pinia / provide-inject**：现有 props drilling 只有"词库数组下发 +
   两个事件上报"一层。功能增多导致跨层传值明显时再评估，记录在 `docs/现状.md`。
6. **ESLint 8 legacy config，够用就好**：现有配置零 error 基线，规则集覆盖了
   本项目关心的全部问题；升级 9 / flat config 是纯迁移工作，不带来新能力。
   升级触发条件：需要某条 legacy 下不可用的新规则，或依赖（vue-eslint-config）
   强制要求时，以独立提交完成。类型导入用内联写法 `import { x, type Foo }`
   才能与 `no-duplicate-imports` 共存；`consistent-type-imports` 对纯 JS 文件
   （`.eslintrc.cjs` 自身）无 TS parser services 会崩溃，已在 overrides 关闭。
7. **dist 入库**：GitHub Pages 的部署方式决定，pre-commit 里跑 `build` 并
   `git add dist/` 是为了让"提交即可部署"成立（实测 test + build 约 14s）。
   若迁移到 Actions 部署，可将 dist 移出版本控制并同步简化 pre-commit——
   两件事必须一起做，只删钩子里的 build 会造成线上 dist 过期。
8. **CountDownIcon 的 `isRunning`/`enableAnimation` 是已知死属性**：动画只由
   `currentTime` 进度驱动。保留是为了不破坏 TypingArea 的既有传参，确认无外部
   调用方后可连同 `:is-running` 绑定一起清理（见 `docs/现状.md` 待办）。
9. **TypeScript 严格选项保留 `noUncheckedIndexedAccess` 等边缘选项**：打字应用
   是数组索引密集型代码（待输入队列、统计数组），该选项在重构中真实拦住了
   `onComing[0]` 空队列崩溃路径；成本（判空守卫）已经付过。`exactOptionalPropertyTypes`
   收益确实小，但同样已付清成本，删除只会放宽约束，没有回报。
10. **工具链版本策略**：框架与构建链冻结大版本（Vue 3.4 / Vite 5 / ESLint 8），
    测试工具跟随 minor 最新（Vitest 2 / Playwright latest）；任何升级以独立提交
    进行且 `pnpm check:all` 通过，不与其他改动混提交。
11. **base.css 是颜色的唯一事实源**：表面/边框/文本等静态色只定义在 CSS 变量里，
    antd token 与图表配色通过 `getCSSVar`（utils.ts）运行时读取，JS 侧不硬编码 hex；
    语义色（success/error/warning/info）由 `useTheme` 的 `@ant-design/colors` 算法
    按明暗生成，种子定义在 base.css 的 `--color-seed-*`（明暗各一套，亮色模式为
    降饱和的柔和值，避免高饱和色在大面积白底上晃眼）。CSS 有消费者的语义色变量
    只有 success/error 两个（watch 回写），warning/info/hover 仅存在于 antd token
    ——不要再往 base.css 加语义色的静态成品定义。

## 4. 已知坑（源码有注释，此处只列索引）

- props 数组按引用变异会污染词库数据：`useTypingInput` 内 push 前逐元组拷贝
  （历史 bug，见 `docs/现状.md` 第五节）。
- 空格字符跨平台表现不一致：统一用 `utils.ts` 的 `regexp` 判定，不写 `=== ' '`。
- HTML 属性不区分大小写：禁用输入写 `contentEditable = 'false'`（字符串）。
